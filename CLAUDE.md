# Hitmen — working agreements

Multiplayer Hitman-like on **Unreal Engine 5.7** (`Hitmen.uproject`, C++ module `Hitmen`).
This repo is the **code-first base**: systems in C++, Blueprints for values and juice. The team
makes graphics, juice, balancing, LD, PCG, VFX and audio. Design: `docs/GAME.md`.
Conventions (prefixes, folders, BP colour code): `docs/Conventions.md`. History: `docs/CHANGELOG.md`.
Everything (docs, comments, commits) is in English.

## Git
- **Work on `dev`.** Commit and push **every change individually** (`git push origin dev`).
  Update `docs/GAME.md` / `docs/CHANGELOG.md` in the same commit as the change they describe.
- Assets go through Git LFS (`.gitattributes`). `.uasset`/`.umap` are **not** `lockable`: lockable
  makes checked-out files read-only and the editor then fails to save. Use `git lfs lock` by hand if needed.
- **End of every prompt:** player builds, commit + push them, then release `main` **without
  checking it out** (a checkout under the open editor reloads everything):
  ```
  git update-ref refs/heads/main $(git commit-tree "dev^{tree}" -p main -p dev -m "Release x.y.z")
  git push origin main
  ```
  main always gets its own merge commit (never fast-forward).

## Build
Engine: `C:\Program Files\Epic Games\UE_5.7`.
- **Compile C++ only through `Tools/Editor/ue_rebuild.ps1`** (`Tools/Editor/Rebuild.bat` for a
  double-click). Never close the editor or run `Build.bat` by hand: the script guarantees the
  editor ends up open again.
  `powershell -NoProfile -ExecutionPolicy Bypass -File Tools/Editor/ue_rebuild.ps1 [-Mode auto|live|full] [-FullOnError]`
  - `auto`: only `.cpp` changed → Live Coding patches the open editor. A header, Build.cs,
    `.uproject` or new file changed, or the editor is closed → stop PIE, save dirty packages,
    close, `Build.bat`, reopen (in a `finally`, even on a failed build) and wait until it answers.
  - Exit 0 ok · 1 compile error (editor open; errors in the Live Coding window, or rerun with
    `-FullOnError` to print them) · 2 the editor would not close or save (nothing touched) ·
    3 the editor did not answer after reopening.
  - Live Coding patches are lost when the editor closes; with the editor closed the script builds
    first, so use it to open the editor too.
- New `UCLASS`/`UPROPERTY`/`UFUNCTION` need a full build (Live Coding cannot add reflected
  types); the script handles it. Batch header changes into milestones to limit restarts.
- The Unreal MCP endpoint is served by the editor (`127.0.0.1:3000/mcp`): it is down while the
  editor is closed, and a session started with the editor closed needs `/mcp` → reconnect.
- Player builds (`RunUAT BuildCookRun`): Shipping → `Builds/Windows`, Development (cheats) →
  `Builds/Windows Dev`. Both are versioned through LFS. RunUAT breaks on an archive path with a
  space: archive to `Builds/_DevTmp`, flatten the nested `Windows/` folder, then move it.

## Editor access
The Unreal MCP server (`mcp__unreal-engine__*`, McpAutomationBridge plugin) drives the open
editor when it is connected. Otherwise use Python remote execution (enabled in `DefaultEngine.ini`):
`python Tools/Editor/ue_remote.py --file <script.py>` runs a script in the open editor.
- Content and maps are generated by `Tools/Editor/` builders (idempotent, safe to re-run):
  `hitmen_content.py` (assets), `hitmen_levels.py` (maps), `hitmen_build_all.py` (both; filter
  with the `HITMEN_BUILD_STEPS` env var). Headless, editor closed:
  `UnrealEditor-Cmd.exe Hitmen.uproject -run=pythonscript -script="Tools/Editor/hitmen_build_all.py"`.
- After rebuilding a map, bake its navmesh (`Tools/Editor/ue_bake_nav.sh`); runtime generation
  does not finish reliably in PIE.
- `Tools/Editor/ue_shot.sh <map>` plays a map in PIE and saves a HighResShot for UI checks.
- Python gotchas: `unreal.Rotator` positional order is (roll, pitch, yaw), so use keywords. Maps
  cannot be saved during PIE, and `editor_request_end_play` is asynchronous.
- Check dirty packages before closing the editor.

## Code rules
- C++ for systems, Blueprints for values, meshes, VFX, SFX and `Juice_On…` events.
- Features are `UActorComponent`s; families use inheritance (character, weapon, ability,
  interactable).
- Objects communicate through delegates bound at BeginPlay; UI has **no hard references** —
  widgets bind to `UHitmenUIEventSubsystem`, PlayerState and GameState delegates.
- No Tick unless continuous; spawn weapons/attachments once and show/hide them.
- All input bindings live in `AHitmenPlayerController`; the pawn only exposes functions.
- Server-authoritative (listen server); movement predicted in `UHitmenCharacterMovementComponent`.
- Tunables: `UPROPERTY(EditDefaultsOnly, Category="Hitmen|…")`, `Project Settings → Hitmen`,
  or data assets. No magic numbers.
- Default keys are AZERTY (ZQSD, `A` manipulation, `E` move ability); crouch and sprint are held.

## Lessons carried from the Unity prototype
- Hearing is graded, occluded, capped to the 1–2 nearest responders; never map-wide.
- Parkour probes handle thin geometry (sills, 30 cm walls) and grab in the air.
- After any AI change, test the attack chain: a seen, armed trespasser is shot within seconds.
- Spectating is a full feature (free fly, follow, multi-view), not a fallback.
- Screenshot every changed screen before calling a UI task done.
